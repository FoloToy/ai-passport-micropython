# AI 智能体开发工作流（白话版）

## 1. 一次只问一个问题

用户不需要懂编程。先问“你想让这个小设备做什么？”，再按顺序追问：开机看到什么、每个按键做什么、屏幕长什么样、是否需要声音/录音/Wi-Fi/蓝牙/电量/休眠、什么现象算完成。每次只问当前缺少的一项，再用白话复述给用户确认。模板见 `requirements-template.md`。

## 2. 优先选择简单方式

默认路径适用于绝大多数应用：固件只烧录一次，AI 只修改用户 `main.py`，通过 USB 串口上传。默认示例不是产品 UI，二次开发必须重新设计页面和流程。

只有确实要改底层接口、I²S/MCLK、LVGL 内部、C 驱动、启动流程、内存或分区时，才选择高级固件开发，并先向用户说明原因。

## 3. 分小步开发

1. 先做一个能显示的最小版本。
2. 再逐个加入按键、声音、网络等功能。
3. 每完成一项，就主动提出上设备运行；找不到设备时提示用户开机并接入可传输数据的 USB 线。
4. 分别说明编译、电脑检查和实机检查的结果。

## 4. 注意事项

- 不得把硬件测试菜单直接当作产品界面。
- LVGL 调用必须在正确的 LVGL 执行上下文中完成。
- 按键回调不能阻塞；录音、播放、扫描和网络请求放到任务或异步流程。
- 不提交凭据、设备私有数据、完整串口日志或临时固件。
- 不要把密码写进代码；未经用户要求不提交、不推送、不创建 PR。
